# Чек-лист 0.6.7 — автоподбор канала Telegram-прокси

Сборка: `ZapretByeDPI-0.6.7-arm64-v8a.apk` (versionCode 20).
Проверять на телефоне, где в 0.6.6 каналы вели себя по-разному:
на Wi-Fi проходил только HTTP 80, на мобильном — TLS 443.

## Что изменилось после 0.6.6

0.6.6 жёстко включала TLS 443. На вашем Wi-Fi это дало `ws tls fail …
timeout` и «все CF домены недоступны», а данные шли только на HTTP 80 —
приходилось переключать канал руками. Теперь канал **подбирается сам**:

- при каждом запуске идёт короткая проверка (опрос каждые 6 с): если
  клиенты подключились (`total ≥ 2`), а CF-соединений нет вообще (`cf=0`)
  дольше 12 с — канал считается мёртвым и включается второй;
- если CF-соединения есть, но данных нет 30 с — тоже переключение;
- как только канал отдал данные, выбор **запоминается для этой сети**
  (отдельно для Wi-Fi и для мобильного интернета) и следующий запуск
  начинается сразу с него, без переключений;
- ручной выбор кнопками `TLS 443` / `HTTP 80` запоминается для сети и
  автоподбор его не перетирает (перезапишется только при новом запуске
  или смене сети);
- при смене сети канал подбирается заново под новую сеть.

В приложении появилась карточка **«КАНАЛ»**: текущий канал крупным текстом,
две кнопки для ручного выбора и подсказка, что канал подбирается сам.
Канал так же виден в уведомлении.

## Что проверить

- [ ] **Wi-Fi, первый запуск.** Выключить мобильные данные, оставить Wi-Fi.
      Telegram → «Запустить». В карточке «КАНАЛ» сначала «… · подбираю
      канал…», через ~15–20 с канал сам становится `Cloudflare HTTP 80`
      (на вашей сети TLS не проходит), Telegram грузит.
      В журнале: `автоподбор: канал Cloudflare TLS 443 не работает … —
      пробую Cloudflare HTTP 80`, затем `CF отвечает`.
- [ ] **Повторный запуск на том же Wi-Fi.** Переключений нет, сразу
      `Cloudflare HTTP 80` — канал запомнен для Wi-Fi.
- [ ] **Мобильный интернет.** Включить данные, выключить Wi-Fi, «Запустить».
      Канал подбирается заново под мобильную сеть (обычно `TLS 443`),
      данные идут. В журнале `Смена сети: …` и `Перезапуск прокси после
      смены сети (мобильная сеть)`.
- [ ] **Wi-Fi ↔ мобильные при работающем прокси.** Оба перехода дают
      перезапуск и правильный канал без ручных действий.
- [ ] **Ручной выбор.** Нажать `TLS 443` — прокси перезапускается на нём,
      выбор запоминается. Вернуть `HTTP 80` — снова работает.
- [ ] **Уведомление** показывает `127.0.0.1:1443 · Cloudflare HTTP 80`
      (или TLS 443) и меняется при переключении.
- [ ] **Здоровье остального.** VPN (YouTube/X) работает и с включённым,
      и с выключенным Telegram-прокси.

## Если канал не подобрался

Прислать «Логи» → «Скачать». Смотреть:

- `telegram channel:` и `telegram probing:` — что было выбрано;
- `telegram channel prefs:` — что запомнено для `wifi` / `cell` / `other`;
- `автоподбор: …` — почему переключался (или не переключался);
- `=== TgWsProxy (logcat, хвост) ===` — причины отказа Cloudflare:
  `ws tls fail … timeout` (TLS к CF режется), `CF fail … handshake 429`
  (лимит общего домена), `все CF домены недоступны`.

Если в нативном логе `429` — это лимит Cloudflare на общий домен, лечится
только своим доменом или CF Worker (`SetCfProxyConfig` / `SetCfWorkerDomains`
в библиотеке есть, поля в UI пока нет).
