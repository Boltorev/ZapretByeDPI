# Этап 2 — чек-лист тестирования

Тестируем только на реальном телефоне. APK берём из GitHub Actions
(артефакт `ZapretByeDPI-debug`).

## 0. Перед установкой

- [ ] На телефоне нет другого активного VPN (или always-on VPN).
- [ ] Отключён приватный DNS, если он мешает диагностике:
      Настройки → Сеть → Private DNS → Off (на время теста).
- [ ] Известна модель телефона и версия Android.
- [ ] Установлен adb на ПК (для логов).

## 1. Установка и старт

- [ ] APK устанавливается без ошибки подписи.
- [ ] Приложение запускается, показывает экран этапа 2.
- [ ] Нажатие кнопки → запрос уведомлений (Android 13+).
- [ ] Затем системный диалог VPN.
- [ ] После разрешения: кнопка зелёная, **РАБОТАЕТ**.
- [ ] В карточке: TUN `tun0`, движок `ciadpi + hev`,
      SOCKS5 `127.0.0.1:1080`.
- [ ] Пресет — `PER_HOST_YT` / `PER_HOST_YT_TLSREC` / `SPLIT1` / `TLSREC` /
      `FAKE` / `FAKE_MD5` / `MULTIDISORDER` / `DISORDER1` / `OOB3`.
- [ ] В шторке есть уведомление, в статус-баре ключ VPN.
- [ ] В журнале есть `protect-сервер готов (self-test OK)`,
      `Пробуем ...`, `TLS media=true api=true`, `QUIC fake готов`,
      `TUN создан`,
      `VPN работает`.

> Первый запуск может занять 5–20 секунд: идёт HTTPS-проба стратегий
> через ciadpi. Дождись `РАБОТАЕТ`, не выключай сразу.

## 2. Трафик

- [ ] Открыть `https://example.com` — страница загружается.
- [ ] Счётчик «Трафик» увеличивается (↓/↑).
- [ ] YouTube открывается, видео воспроизводится.
- [ ] Discord в браузере открывается.
- [ ] Проверить IP: `https://2ip.ru` показывает реальный IP провайдера
      (это не VPN-шифрование, а локальный обход DPI — так и должно быть).

## 3. Остановка

- [ ] Нажать кнопку — статус «Остановлен», уведомление и ключ исчезают.
- [ ] Интернет работает напрямую.
- [ ] Запустить снова — поднимается без перезагрузки.
- [ ] Остановить из уведомления — тоже работает.

## 4. Ошибки и логи

Главный способ — кнопка **«Скачать»** в карточке «ЖУРНАЛ». Она сохраняет
`zapret-log-YYYYMMDD-HHmmss.txt` через системный диалог. Внутри:

- устройство, Android, ABI, версия приложения;
- состояние VPN и выбранная стратегия;
- self-test protect и статистика TUN (`tx/rx`);
- список нативных библиотек;
- полный AppLog;
- хвосты `ciadpi.log` и `hev.log`.

Пришли этот файл + модель телефона, оператора и что именно не открылось.

Если нужен adb:

```bash
adb logcat -c
# включить VPN, подождать 30 секунд, открыть YouTube
adb logcat -d -s Zapret/VpnService Zapret/ciadpi Zapret/hev ZapretHev Zapret/Stats > logcat.txt
adb shell ps -A | grep ciadpi > ps.txt
adb shell run-as com.zapret.byedpi ls -l files > files.txt
adb shell run-as com.zapret.byedpi cat files/hev.log > hev.log
adb shell run-as com.zapret.byedpi cat files/ciadpi.log > ciadpi.log
```

### Как читать отчёт

| Что видно | Где проблема |
|---|---|
| `TLS media=true api=true` у выбранной стратегии, но страницы не открываются | DNS/hev/TUN, не ciadpi |
| `TLS media=false api=true` у `PER_HOST_YT` | остаётся QUIC fake; видео может работать через UDP |
| `TLS media=false api=false` у всех стратегий | Сеть/провайдер/аргументы ciadpi |
| `TUN tx_packets=0` | Трафик приложений не попадает в VPN (маршрут/Per-App) |
| `TUN tx_packets>0, rx_packets=0` | hev не возвращает ответы / ciadpi |
| `TUN rx_packets>0`, сайты не открываются | DNS или приложение |
| `protect self-test failed` | защита по UID, protect не используется |

## 5. Что считается успехом этапа 2

- VPN поднимается и не отваливается 10+ минут.
- Трафик реально идёт через ciadpi (счётчик растёт).
- YouTube/Discord открываются (если стратегия подходит провайдеру).
- Остановка и повторный запуск работают.
- При ошибке приложение не падает, а показывает причину.

Если YouTube не открывается, но трафик растёт — это не баг трубы,
а неподходящая стратегия. Её лечим на этапе 3 пресетами и ротацией.
