- [ ] На главной сверху видно `Версия 0.6.5`.

      `zapret-log-0.6.5-20261128-202725.txt`.
- [ ] Если на GitHub тег новее, на главной появляется плашка
      «Доступна новая версия X — нажмите, чтобы обновиться»,
      тап открывает страницу релизов.
- [ ] Если версия актуальна, плашки нет.

      «Стратегия: … · вариант N», не только пресет.

      (`Cloudflare true -> false` в журнале).

## 0.6.4: быстрый старт на «мёртвых» сетях

- [ ] На сети, где Google режется целиком, статус уходит из «Подключение»
      за ~40–50 секунд (не за минуты) и становится «Работает» с fallback.
- [ ] В карточке состояния во время перебора видно `Проверка N/9`.
- [ ] В журнале есть `Пробуем N/9 <стратегия>` и, при исчерпании бюджета,
      `Перебор остановлен по времени`.
- [ ] В логе пробы одного хоста не больше 2 адресов (`HTTPS probe … via /IP`).
- [ ] На нормальной сети старт по-прежнему быстрый (первый кандидат).

## 0.6.3: медиа X и watchdog Telegram

- [ ] X: открыть ленту, полистать, открыть пост с картинкой и видео,
      открыть комментарии — всё грузится, а не «крутится вечно».
- [ ] В журнале есть `Auto: xm: pbs.twimg.com OK` (проверка идёт реальным
      HTTP-запросом, а не только TLS-рукопожатием).
- [ ] Если медиа не грузится, в журнале появляется
      `Auto: xm: pbs.twimg.com FAIL …` и `AUTO xm: … index=…` — то есть
      медиа X ротируется отдельно от API X.
- [ ] `NO_DATA` в логе означает «рукопожатие прошло, данных нет» — это
      провал стратегии, а не сети.
- [ ] Telegram: если клиент отправляет данные, а `down` стоит 90 секунд,
      в журнале появляется `watchdog: down стоит … — перезапуск прокси`,
      прокси поднимается, `down` снова растёт.
- [ ] Watchdog не срабатывает, когда Telegram просто молчит (висящее
      соединение без трафика) — это штатное состояние.
- [ ] Перезапусков не больше одного в 10 минут (в журнале
      `перезапуск был недавно, жду`).
